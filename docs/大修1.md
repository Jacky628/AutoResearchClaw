# 大修 1：评审去同源 + 多模型辩论引擎

> 日期：2026-06-01（含 2026-05-31「生成-评审模型分离」与次日「多模型辩论」两批改动）
> 修订：2026-06-04 —— 更正「多模型辩论」接线范围为 **Stage 14 / 18**（此前误记为含 Stage 8；
> 实际接线于本日真正落盘，详见第二批开头「勘误」）。
> 目标：把 AutoResearchClaw 从「同一个模型自己生成、自己评审、自己打分」的循环论证，
> 升级为「不同模型分饰角色 → 交锋反驳 → 独立裁判打分综合」的真·多模型对抗体系。
> 全部改动 **opt-in，默认行为零变化**。

---

## 背景：为什么要做（review 发现）

对项目做深度 review 时，用 `file:line` 核实出两个根本短板：

1. **评 = 生 = 判 同源**：Stage 18 同行评审 / Stage 19 修订 / Stage 20 质量门，全部由**同一个 LLM 实例**完成
   （`executor.py` 每个 stage 只构造一个 `llm = LLMClient.from_rc_config(config)` 原样下传）。
   生成者给自己打分 → 系统性自我偏好（self-preference），评审可信度极低。
2. **辩论又浅又假**：
   - Stage 8 假设生成、Stage 14 结果分析虽有「多视角」，但是 `_multi_perspective_generate` +
     `_synthesize_perspectives`——**同一个模型**分饰多角色、各发言一次、**互不可见**、单次综合，**没有交锋、没有打分择优**。
   - Stage 18 同行评审更是「伪辩论」：`prompts/ml.py` 里一句 *"Simulate peer review from 3 reviewers"*，
     **同一个模型一次调用假装 3 个 reviewer**。
   - Stage 15 研究决策是单模型单次判定。

横向对标（AI Scientist v2 树搜索、Google co-scientist 多 agent 锦标赛、MLR-Bench 指出 coding agent 80% 伪造结果）
后确认：**「评审去同源 + 真多模型辩论」正是当前前沿集中发力的方向**。

# 第一批：生成-评审模型分离（P0-3）

## 核心思想
让**批评/裁决**来自与作者**不同**的模型：作者负责生成与修订，独立模型负责评审与质量门裁决。

## 改了什么

### 1. 配置（`researchclaw/config.py`）
`LlmConfig` 新增 5 个字段（默认空 = 禁用，向后兼容）：
```python
reviewer_model: str = ""        # 空 => 评审复用生成器（旧行为）
reviewer_provider: str = ""     # 缺省沿用主 provider
reviewer_base_url: str = ""     # 缺省沿用主 base_url
reviewer_api_key: str = ""
reviewer_api_key_env: str = ""
```
两种用法：仅给 `reviewer_model` → 同端点换模型；给全套 → 完全独立 provider（如 生成=GPT / 评审=Claude）。

### 2. 客户端工厂（`researchclaw/llm/client.py` + `llm/__init__.py`）
- `LLMClient.reviewer_from_rc_config()` —— 构造独立评审客户端：复用现有 provider-preset / Anthropic-adapter
  逻辑，缺省字段回落主配置；`fallback_models=[]`（**不回落到作者模型**，保独立性）。
- `build_reviewer_llm(config)` —— 便捷封装；ACP 或未配置时返回 None（调用方回落生成器）。

### 3. 接入评审阶段（`researchclaw/pipeline/stage_impls/_review_publish.py`）
- **Stage 18 peer_review** 与 **Stage 20 quality_gate** 改用 `reviewer_llm`（未配置则回落生成器）。
- **Stage 19 paper_revision 仍用作者模型**——这是去耦核心：作者写/改，独立模型批/判。
- 加 `_INDEPENDENT_REVIEWER_PREFIX`：在评审/裁决 system prompt 前声明「你是独立评审、与作者模型不同、
  默认挑错而非背书」（即便同模型也降低 self-preference）。
- **出处留痕**：`reviews.md` 加注释头、新增 `review_provenance.json`、`quality_report.json` 记录
  `author_model` / `judge_model` / `independent`，可审计。

### 4. ARC-Bench 评测独立性（`experiments/arc_bench/scripts/judge.py`）
- 同源守卫：若 `ARC_JUDGE_MODEL == ARC_AUTHOR_MODEL` 则报错，需 `ARC_ALLOW_SAME_MODEL_JUDGE=1` 显式放行。
- judge system prompt 补「独立评审」声明。

### 5. 文档与示例
`config.researchclaw.example.yaml`、`CLAUDE.md` 加 reviewer 字段说明与示例。

## 实际启用（你的 `config.arc.yaml`）
```yaml
llm:
  primary_model: "anthropic/claude-sonnet-4.6"   # 作者：生成 + 修订
  reviewer_model: "openai/gpt-4o"                 # 评审 + 裁决（经 OpenRouter 调 OpenAI gpt-4o）
```
即：**生成/修订 = Claude Sonnet 4.6，评审/裁决 = gpt-4o**，复用同一个 `OPENROUTER_API_KEY`，无需额外凭证。

# 第二批：多模型辩论引擎（Stage 14 / 18）

> **勘误（2026-06-04 修订）**：本批最初记录为「Stage 8 / 14 / 18 三阶段接线」，但因上一轮工具回显延迟，
> `_synthesis.py`(Stage 8) / `_analysis.py`(Stage 14) 的接线**实际未落盘**——`run_debate` 当时是死代码，
> 三个阶段仍走旧的单模型多视角。已于 2026-06-04 修正：
> - **Stage 14 / 18 已真正接入 `run_debate`**（见下文 §5，附 file:line 与回归测试）。
> - **Stage 8 改用 best-of-N 锦标赛**（见独立文档「第6条」），**不接 debate**——故本批范围收窄为 Stage 14 / 18。

## 核心思想
把「单模型分饰多角色、各说一次、单次综合」升级为统一的
**「多模型 × 多视角 × 多轮交锋 × 独立裁判」** 引擎，Stage 14 / 18 共用。

## 改了什么

### 1. 配置（`researchclaw/config.py`）—— 复用现有模型，不新增模型列表
```python
debate_enabled: bool = False    # opt-in 总开关，默认关 = 行为零变化
debate_rounds: int = 1          # 交锋（反驳）轮数；0 = 只并行+裁决
```

### 2. 辩论模型池（`researchclaw/llm/__init__.py` 的 `build_panel_llms`）
- `debate_enabled=False` 或 ACP → 返回 `[]`（走旧路径）。
- 否则把 **`primary_model` + `reviewer_model` + `fallback_models`** 按模型名**去重**组成池，
  每个模型克隆成独立单模型客户端（`fallback_models=[]`），共享主端点与 adapter。

### 3. 辩论引擎（新文件 `researchclaw/pipeline/debate.py`，`run_debate()`）
单一入口，被三阶段共用，流程：
1. **角色↔模型轮流绑定**：`panel[i % len(panel)]`，让不同模型各持一个立场（角色比模型多时回绕）。
2. **首轮发言**：每角色独立 `chat()`，落盘 `{role}.r0.md`。
3. **交锋轮**（重复 `debate_rounds` 次）：给每个角色拼入**其他角色上一轮全文** + `debate_rebuttal`
   反驳子 prompt，要求反驳弱点、强化/修正己方立场，落盘 `{role}.r{n}.md`。
4. **裁判**：独立 judge（复用 `reviewer_model`）对各角色最终立场**打分(1-10) + 排序 + 综合**，
   产出最终文本 + `debate_record.json`（panel 模型、角色绑定、轮次、judge 独立性等）。
- 容错：单角色失败跳过，全失败回落旧综合/默认产物；
  保留 `ARC_ABL_DISABLE_DEBATE` 消融钩子，新增 `ARC_DEBATE_ROUNDS` 环境覆盖。

### 4. 反驳 prompt（`researchclaw/prompts/shared.py`）
新增 `debate_rebuttal` 子 prompt（domain 无关）：「这是你上一轮的立场 + 其他视角发言，请反驳并修正己方」。

### 5. 阶段接线（薄改，不动 executor 分发签名）
每阶段先 `panel = build_panel_llms(config)`，非空走 `run_debate(...)`，否则保持原路径：
- **Stage 14 结果分析**（`_analysis.py:598-636`）：roles=`debate_roles_analysis()`
  （optimist / skeptic / methodologist），synth=`analysis_synthesize`，judge=`build_reviewer_llm`，
  落盘 `analysis.md` + `stage-14/perspectives/debate_record.json`。
- **Stage 18 同行评审**（`_review_publish.py:217-240`）：用引擎内联的 `_REVIEW_DEBATE_ROLES`
  （方法学 / 领域 / 统计严谨 三个独立评审角色），synth=新增 `review_synthesize` 子 prompt，
  judge=独立 reviewer → 多模型各自评审 → 交锋 → 综合为 `reviews.md`，
  落盘 `stage-18/debate/debate_record.json` + 保留原有 `review_provenance.json`。
  **「伪辩论」由此升级为真·多模型辩论**。
- **Stage 8 假设生成**：本批**不接 debate**——改用 best-of-N 锦标赛（独立文档），`_synthesis.py` 走
  `tournament > legacy` 两条路径，不调用 `run_debate`。
- 回归测试 `tests/test_rc_executor.py::TestDebateWiring`（4 例）守护 Stage 14/18 接线，防止再次退化为死代码。

### 6. 文档与示例
`config.researchclaw.example.yaml`、`CLAUDE.md` 加 `debate_enabled` / `debate_rounds` 说明。

## 实际启用（你的 `config.arc.yaml`）
```yaml
llm:
  primary_model: "anthropic/claude-sonnet-4.6"
  reviewer_model: "openai/gpt-4o"
  fallback_models:
    - "google/gemini-2.5-pro"        # deepseek-chat 已按你的要求删除
  debate_enabled: true
  debate_rounds: 1
```
辩论池 = **claude-sonnet-4.6 + gpt-4o + gemini-2.5-pro**（3 个，去重自上面三处）；裁判 judge = gpt-4o。

每阶段产出 `stage-XX/.../debate_record.json` 与各角色各轮 `{role}.r{n}.md`。

## 设计取舍 / 注意事项
- **opt-in、向后兼容**：`reviewer_model` 空 + `debate_enabled: false`（默认）时，所有阶段走原路径，行为零变化。
- **成本**：辩论开启后每阶段约 `角色数×(1+rounds)+1` 次调用（≈7 次/阶段 × 2 阶段 = Stage 14/18）。
  可调 `debate_rounds` / `ARC_DEBATE_ROUNDS`，或 `debate_enabled: false` 关闭。
- **辩论池来自现有模型**（按用户选择「复用现有模型」），含 fallback；deepseek-chat 已按要求移除。
- **未做（可后续）**：Stage 15 研究决策的多模型投票；跨 domain（hep/biology）专用的 `DEBATE_ROLES_REVIEW`
  （当前 Stage 18 用引擎内联的通用三评审角色 `_REVIEW_DEBATE_ROLES`）。
