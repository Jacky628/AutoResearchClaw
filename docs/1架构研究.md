# AutoResearchClaw 架构研究文档

> 目标:把"从一个研究 topic 自动产出会议级 LaTeX 论文"的 23 阶段状态机讲透——不止列出要点,而是阐述每个机制**如何运作、数据如何流动、为何这样设计、有哪些守卫与边界**。所有结论带 `file:line` 证据,基于真实代码。

---

## 0. 系统全貌:一句话与一张图

ResearchClaw 本质是**一个确定性的顺序状态机,外挂"每阶段一次结构化 LLM 调用"和"人机协作(HITL)闸门"**。它把科研流程拆成 23 个离散阶段,串成 `STAGE_SEQUENCE`;每个阶段是一个纯函数式的执行单元:

```
读上游产物文件 → 选领域 prompt 模板并填充 → 调 LLM → 多级容错解析输出
→ 落盘到 stage-NN/ → 契约校验产物 → (若是闸门)阻塞等人审 → 写 checkpoint
```

设计哲学贯穿全代码:
- **可恢复**:每个完成的阶段写原子 checkpoint,崩溃后从下一阶段续跑。
- **人可介入**:3 个硬闸门(5/9/20)+ 6 种 HITL 策略,人可在任意点暂停、审批、改产物、注入指导。
- **优雅降级**:LLM 不可用时用模板兜底;实验反复失败时强制 PROCEED 并标注质量警告——宁可产出一篇带警告的论文,也不死循环。
- **抗幻觉**:论文阶段把 LLM 的"自由发挥"约束在真实实验数据上,导出前还要做引用核验和数字消毒。

## 2. 状态机内核:advance() 如何计算每一步

整台机器的"大脑"是 `advance(stage, status, event, ...)`(`stages.py:250-359`)。它是个纯函数:给定**当前阶段、当前状态、触发事件**,返回一个 `TransitionOutcome`(下一阶段、下一状态、是否要写 checkpoint、决策标签)。合法状态迁移由 `TRANSITION_MAP`(`:187-201`)约束,`advance()` 在其框架内按事件分支:

**① START → RUNNING**(`:266-273`):pending/retrying/paused 三种"休眠态"收到 START 都进入 running,`next_stage=stage`(原地执行)。

**② SUCCEED → 分叉**(`:276-290`)——这是**闸门决策点**:
```python
if event is SUCCEED and status is RUNNING:
    if gate_required(stage, hitl_required_stages):
        return TransitionOutcome(status=BLOCKED_APPROVAL, next_stage=stage,
                                 checkpoint_required=False, decision="block")
    return TransitionOutcome(status=DONE, next_stage=NEXT_STAGE[stage],
                             checkpoint_required=True)
```
关键设计:**闸门成功执行后不写 checkpoint**(`checkpoint_required=False`)。因为这个阶段可能被人拒绝回滚,过早落盘会让续跑误以为它已通过。

**③ APPROVE → DONE**(`:293-299`):人审通过,此时才 `checkpoint_required=True`——续跑总是从"最后一个人类批准的里程碑"开始。

**④ REJECT → 回滚**(`:302-310`):
```python
if event is REJECT and status is BLOCKED_APPROVAL:
    return TransitionOutcome(stage=target_rollback, status=PENDING,
                             rollback_stage=target_rollback,
                             checkpoint_required=True, decision="pivot")
```
`target_rollback` 取自 `GATE_ROLLBACK[stage]`,被拒阶段重置为 PENDING 待重跑。checkpoint 记录"已回退到 stage X",防止误重跑被拒阶段。

**⑤ FAIL/RETRY/PAUSE**(`:323-339`):running 出错→failed(写 checkpoint 记住卡点);failed+retry→retrying;failed→paused(交人)。

> **为什么用纯函数 + TRANSITION_MAP?** 状态迁移与副作用(落盘、调 LLM)解耦,使整个控制流可单元测试、可推理、可重放。

## 3. 闸门与回滚:三道硬闸 + 领域感知回滚

**闸门集合**(`stages.py:109-115`):`{LITERATURE_SCREEN(5), EXPERIMENT_DESIGN(9), QUALITY_GATE(20)}`——分别守在"文献筛选后、实验设计后、论文质检处"。

**`gate_required()` 谓词逻辑**(`:214-242`)比看上去复杂:
```python
is_gate = stage in GATE_STAGES
is_hep_ph_codegen_gate = (stage is CODE_GENERATION and profile == "hep_ph")
if not is_gate and is_hep_ph_codegen_gate: is_gate = True
if not is_gate: return False
if is_hep_ph_codegen_gate: return True          # hep_ph 下 stage 10 永远是闸门
if hitl_required_stages is not None:            # 可被配置裁剪
    return int(stage) in frozenset(hitl_required_stages)
return True
```
**hep_ph(高能物理)特例**:stage 10 代码生成被强制升格为闸门,且**无视 `hitl_required_stages` 裁剪**。原因:下游 ColliderAgent 要跑 FeynRules/MadGraph 这种极昂贵、不可逆的对撞机模拟,人必须先审 `collider_plan.md` 再烧算力。这是 profile 级不变量。

**回滚目标**(`GATE_ROLLBACK`,`:118-123`)是**领域感知**的:
| 拒绝的闸门 | 回退到 | 语义 |
|-----------|--------|------|
| 5 文献筛选 | 4 文献采集 | 文献太差→多采集 |
| 9 实验设计 | 8 假设生成 | 方案不行→换假设 |
| 10 代码(hep_ph) | 9 实验设计 | 重新设计 |
| 20 质检 | 16 论文大纲 | 重写论文 |

**非关键阶段**(`NONCRITICAL_STAGES = {20, 21}`,`:140-146`):质检和归档失败不阻断交付。注意 **23 引用核验是关键的**——幻觉引用必须阻断导出。

## 4. 主循环与 PIVOT/REFINE 递归

### 4.1 主循环 `execute_pipeline()`(`runner.py:431-912`)

遍历 `STAGE_SEQUENCE`,`_should_start(stage, from_stage, started)`(`:35-38`)控制"到达起点才开跑"。每阶段 `execute_stage()` 后按返回状态分支:
- **DONE** → `_write_checkpoint()`,前进
- **BLOCKED_APPROVAL** + `stop_on_gate` → break(交人审)
- **FAILED** → 若 `skip_noncritical` 且属非关键阶段则跳过,否则 break
- **PAUSED / REJECTED** → break

### 4.2 决策回滚:PROCEED / REFINE / PIVOT

stage 15 产出决策后,若是 refine/pivot,主循环进入**递归回滚**(`runner.py:700-813`),这是全系统最复杂的控制流:

```python
DECISION_ROLLBACK = {"pivot": HYPOTHESIS_GEN(8), "refine": ITERATIVE_REFINE(13)}
MAX_DECISION_PIVOTS = 2
```
- **PIVOT**:假设根本错了→回 stage 8 重新生成假设(丢弃旧假设)。
- **REFINE**:假设没问题、是实验执行有 bug→回 stage 13 重跑(保留假设)。agent 模式(collider/biology/stat)下 refine 改回 stage 12。

**递归前先给目录版本化**——`_version_rollback_stages()`(`:1234-1276`)有两种行为:
```python
if incremental and stage_num >= EXPERIMENT_RUN:   # agent 模式 refine
    shutil.copytree(stage_dir, version_dir)        # 复制:保留工作区供增量改进
else:
    stage_dir.rename(version_dir)                  # 改名:stage-NN → stage-NN_v{n}
```
**为何区分 copy/rename?** 普通 refine 改名即可(下次从干净状态重跑);但 agent 模式要复制,让重新派出的 ColliderAgent 能读到上一轮的 CSV/KO 表做**增量改进**而非从零重算。

然后**递归调用 `execute_pipeline(from_stage=rollback_target)`**,递归返回后调 `_promote_best_stage14()` 提升最优结果,再 break(递归已处理后续)。

**防死循环 + 优雅降级**:
- `pivot_count >= 2` 时不再回滚,调 `_check_experiment_quality()`(`:1431-1510`),质量差则写 `quality_warning.txt` 并强制 PROCEED。
- R6-4 守卫:若连续 REFINE 都产出空指标(`_consecutive_empty_metrics`),立即强制 PROCEED——实验在静默失败,再循环也没用。

### 4.3 `_promote_best_stage14()`:为什么必须"提升最优"(`:1313-1429`)

回滚后目录里有 `stage-14/`(最新,可能是退化的)和 `stage-14_v1/`、`stage-14_v2/`(历史)。论文阶段(16-22)只读 `stage-14/experiment_summary.json`,若不提升就会用到最差的一轮。该函数:
1. 扫所有 `stage-14*`,按主指标(`metric_key`/`metric_direction`)排序;
2. **BUG-226 守卫**:最小化指标时,若"最优值"比次优小 1000 倍以上,判定为退化(NaN/训练崩溃),弃用取次优;
3. 先把最优写到根目录 `experiment_summary_best.json`(BUG-223,任何提前返回前都先写),再把最优的 summary/analysis/charts 复制进 `stage-14/`。

## 5. Checkpoint 与续跑

**写**(`_write_checkpoint()`,`runner.py:78-107`)用**原子写**:先 `mkstemp` 写临时文件,再 `Path(tmp).replace(target)` 原子改名——进程中途崩溃也不会留下半截损坏的 checkpoint。内容含 `last_completed_stage/name/run_id/timestamp`,并内嵌 `hitl_session.hitl_checkpoint_data()`(若有)。

**读**(`read_checkpoint()`,`:126-143`)返回的是**下一个待执行阶段**,不是已完成的:在 stage 5 崩溃,checkpoint 记 5,读出来返回 stage 6。`resume_from_checkpoint()`(`:146-151`)据此喂给 `from_stage`。

另有 `heartbeat.json`(PID/last stage,用于探活)和 `pipeline_summary.json`(`:41-75`,全程统计)。

## 6. 单阶段执行的完整生命周期(7 阶段)

`execute_stage()`(`executor.py:594-821`)是"分派器 + 守卫层",把每个阶段包成统一的 7 步流水:

**Phase 1 — HITL 前置钩子**(`_run_hitl_pre_stage`,`:200-254`):任何工作前先问 HITL 会话要不要暂停。可**短路**:`SKIP`→直接返回 DONE(不执行);`ABORT`→返回 FAILED 终止;若人给了指导文本,写进 `stage_dir/hitl_guidance.md` 供阶段逻辑消费;返回 `None` 才正常往下。

**Phase 2 — 输入契约校验**(`:615-627`):据 `StageContract.input_files` 用 `_read_prior_artifact()` 找上游产物,缺则立即 FAILED(`decision="retry"`),**不调执行器**——快速失败,防止级联错误。

**Phase 3 — 构建 LLMClient + PromptManager**(`:639-661`):LLM 是**可选的**,创建失败则 `llm=None`,阶段降级到模板兜底(如 stage 1 无 LLM 时套用模板生成 goal)。PromptManager 按 `config` 选领域 bank,每阶段构建一次。

**Phase 4 — 分派**(`:651-669`):`_STAGE_EXECUTORS[stage](stage_dir, run_dir, config, adapters, llm=llm, prompts=prompts)`。对不接受 `prompts` kwarg 的旧实现,捕获 `TypeError` 后无 prompts 重试(向后兼容)。

**Phase 5 — 输出契约校验**(`:680-705`):据 `output_files` 检查产物存在且非空(目录则检查非空目录),不达标把 DONE 降级为 FAILED。

**Phase 6 — PRM 质量评估 + 闸门检查**(`:707-794`):若启 MetaClaw PRM,对 5/9/15/20 评分写 `prm_score.json`(异常**非阻断**)。再 `gate_required()` 判闸门:非 `auto_approve_gates` 则置 BLOCKED_APPROVAL 并发通知。

**Phase 7 — 元数据 + HITL 后置钩子**(`:799-821`):写 `stage_health.json`(耗时/状态/产物数)和 `decision.json`(路由)。`_run_hitl_post_stage`(`:257-437`)做:成本守卫(超预算暂停)、SmartPause(PRM<0.7 可触发复审)、人可 APPROVE/REJECT/EDIT/COLLABORATE/SKIP/ABORT,其中 COLLABORATE 进入 stdin 交互聊天循环(`:440-564`)。

## 7. 共享 LLM 设施:容错是第一关切

### 7.1 `_chat_with_prompt()`(`_helpers.py:744-802`)
单轮调用的统一包装,容错点:
- **指数退避重试**:`delay = 2**(attempt+1)`(2s、4s、8s)。
- **HTTP 400 自动降级 json_mode**:某些 OpenAI 兼容代理不支持 `response_format`,报 400 时自动关掉 json_mode 重试。
- **`strip_thinking=True`**:剥掉 `<think>...</think>`。原因:o3/o4 等推理模型会吐思维链,这些标签会破坏下游 JSON/YAML 解析器和 LaTeX 编译。

### 7.2 `_safe_json_loads()` 四级容错解析(`:511-580`)
LLM 输出很脏(前后缀废话、markdown 包裹、思维链),所以解析分四级:
1. **直接 `json.loads`**;
2. **抽 ```json``` 代码围栏**;
3. **平衡花括号匹配**:扫所有 `{...}` 配对,按长度降序取最大的合法 dict(LLM 常有前导废话,最大块通常是真数据);
4. **平衡方括号** 抽数组 `[...]`;
全失败返回调用方给的 `default`,保证不崩。

### 7.3 `_read_prior_artifact()` 与版本去优先(`:397-421`)
`_stage_sort_key`:`stage-13` → `("stage-13", 0)`(优先级最高),`stage-13_v2` → `("stage-13", -2)`(更低)。逆序扫描时**非版本化目录胜出**。设计意图:重试产生 `_vN` 目录,下游应优先读原始(非版本化)那份,只有原始缺失时才退到版本化恢复版,避免一次坏重试污染下游。

### 7.4 多角色辩论 + 综合(stage 8 用)
- `_multi_perspective_generate()`(`:1678-1719`):对每个角色(ML:innovator/pragmatist/contrarian;HEP:theorist/phenomenologist/experimentalist)各调一次 LLM,产出存 `perspectives/<role>.md`。带消融钩子 `ARC_ABL_DISABLE_DEBATE=1` 可退化为单角色做 A/B。
- `_synthesize_perspectives()`(`:1722-1738`):把多视角拼成上下文,用 synthesizer 子 prompt 收敛成统一假设集。**发散(各角色争论)与收敛(综合)分离**,对抗群体思维。

### 7.5 PromptManager(`prompts/manager.py`)
- `_load_bank()`(`:74-94`):`hep_ph→hep.py`、`biology_metabolic→biology.py`、其余→`ml.py`(未知域静默回退 ml)。构建期定域,全程一致。
- `for_stage()`(`:214-244`):`_render` 用正则 `\{(\w+)\}` 做变量替换(只匹配裸标识符,故 JSON schema 里的 `{...}` 不会被误替),再依次追加 `evolution_overlay`(跨轮经验)和 config 的 `extra_prompts`,返回 `RenderedPrompt(system, user, json_mode, max_tokens)`。
- prompt 结构:每 stage `{system, user, json_mode, max_tokens}`;`shared.py` 存 `_DEFAULT_BLOCKS`(~20 可复用片段)、`_DEFAULT_SUB_PROMPTS`、`SECTION_WORD_TARGETS`。

## 8. 关键阶段内部机制

### 8.1 Stage 8 假设生成:三层兜底(`_synthesis.py:92-198`)
1. 多角色辩论生成视角;**BUG-S2 守卫**:若全部角色失败(空 perspectives),立即用 `_default_hypotheses()` 兜底,绝不拿空上下文喂 LLM(否则纯幻觉)。
2. 至少一个视角成功才调综合。
3. 若存在 `hitl_guidance.md` 则据人类指导精修假设。
4. 包装成 Workshop 候选供 UI 审阅(失败静默跳过)。
5. **新颖性核验**:`check_novelty()` 对比已采集论文,产出 `novelty_score/assessment/recommendation`——**非阻断**(外部 API 超时不拖垮本阶段)。

### 8.2 Stage 10 代码生成:复杂度驱动的三层路由(`_code_generation.py:227-800`, `code_agent.py`)
```
① Beast Mode(OpenCode)——复杂度评分 > 阈值(默认 3.5)才启
   信号:多文件、自定义算法、本 run 历史失败次数;非 auto 时经 HITL 确认
   成功→写文件跳过 ②③;失败→落到 ②
② CodeAgent(高级 LLM)——蓝图规划 → 顺序生成 → 沙箱内执行修复
   Phase1 出 YAML 架构蓝图(BUG-178 预处理含 ':'/'->' 的值避免 YAML 崩)
   Phase2 逐文件生成 + 硬校验(语法/安全/import)+ exec-fix 循环
   Phase3 可选树搜索(并行多实现,沙箱择优,昂贵,opt-in)
   Phase4 coder-reviewer 多轮复审(默认 2 轮)
③ 旧单发——直接一次 LLM 调用兜底
```
**修复循环**:`max_repair=5`,每轮 `validate_code()` 不过就把问题喂回 LLM 让它改,过了就 break。

### 8.3 Stage 12 执行 + Stage 13 精修(`_execution.py:119-850`)
- **模式路由**(`:149-287`):collider_agent 读 `collider_plan.md` 跑 ColliderAgentSandbox;sandbox/docker 经 `create_sandbox` 跑 `run_project` 或 `run`。
- **指标提取守卫**:**R6-2** 即使退出码 0,stdout 含 `FAIL:`/`NaN/divergence`/`Traceback` 也判 failed;超时但有指标→`partial`;<5 秒完成→警告 benchmark 可能过易(P1)。
- **精修循环**(`:843-893`):最多 `min(max_iterations, 10)` 轮,带 **BUG-57 墙钟上限**(默认 1.5× 单轮预算)防无限跑;每轮跑实验、`_find_metric` 模糊匹配指标(BUG-214 先精确后子串,避免 "accuracy" 误配 "balanced_accuracy")、与基线比较;**连续 3 轮无改进收敛**;连续 2 轮 NaN/Inf 暂停;最优值跌破基线 50% 判退化暂停。
- **BUG-58 恢复**:PIVOT 回到 13 时,扫所有 `stage-13_v*` 选 `best_metric` 最高的精修代码,而非用原始未精修代码。

### 8.4 Stage 14 分析 + Stage 15 决策(`_analysis.py`)
- **Stage13 合并(BUG-165)**:只有当精修结果**确实更好**才替换 stage 12 数据,防止 78.93%→8.65% 的灾难性回归。
- **条件汇总 + P0-D 救援**:解析 `condition/metric/seed` 格式;全部解析失败时合成单个 `default_condition` 避免 `cond_count=0` 惩罚。
- **消融有效性(P8 / R5-BUG-03)**:两两比较条件,完全相同→`ABLATION FAILURE`(区分参数没在代码里生效),<1% 差异→`ABLATION WARNING`(平凡消融)。
- **配对统计检验(R33)**:有 ≥3 个公共种子时,流水线自己用 scipy 算配对 t 检验;若实验代码自报的 t 统计量全相同或过稀疏,改用流水线算的——侦测实验代码统计检验损坏/重复。

### 8.5 Stage 17/23 抗幻觉(`_paper_writing.py`, `_review_publish.py`)
- **Stage 17 注入真实指标(R4-2/BUG-29)**:`_collect_raw_experiment_metrics` 收集 stage12/13/collider 的真实数字,在 prompt 里硬性约束"Results 表里每个数必须来自以下数据,不许编、不许乱舍入、不许把原始路径粘进论文"。**BUG-207** 选 sandbox 条目时取"主指标最高 + 指标集最丰富"双标准(老 bug 只看数量,导致 1.29% 准确率的 `sandbox_after_fix` 因多 6 个键而盖过 78.93% 的 `sandbox`)。
- **Stage 23 数字消毒**(`_sanitize_fabricated_data`,`:716-1160`):从 `experiment_summary_best.json`(BUG-222 用提升后的最优)递归收集所有有限数字作为"已验证集";扫论文表格/正文,**1% 相对容差**(容许 0.734↔73.4% 的百分比/小数换算);**BUG-175 白名单**放行常见超参(学习率、batch、≤20 的小整数)和 Adam betas;**表格分类**跳过超参表和统计检验表(t/p/effect size 本就不在 summary 里);**BUG-184 逐列**只消毒数值结果列,保留方法名/条件标签;未验证数字在结果区替换为 `---` 或 `[value removed]`。
- **Stage 23 引用核验(BUG-194)**:解析缺失引用键 `(author, year, hint)`,三层策略对照已采集论文解析/补全,剔除幻觉引用。

## 10. LLM 客户端(`llm/client.py`)

`LLMClient` 维护 `_model_chain = [primary] + fallbacks`(`:98`)。`chat()`(`:179-240`)逐个模型尝试,异常则记警告换下一个,全挂才抛 RuntimeError——**对用户透明**:gpt-5.2 不可用自动试 gpt-5.1。

`_call_with_retry()`(`:285-382`)退避 + 抖动:`delay = min(base*2^attempt, 300s) + uniform(0, 30%)` 防惊群。错误分类:403+"not allowed to use model"→直接换 fallback;400 仅当含 rate limit/overloaded 等关键词才重试(Azure 怪癖),否则当真 bad request 抛出;429/5xx/529→重试。`preflight()`(`:242-283`)区分 401(坏 key)/403(模型禁用)/404(端点错)/429/timeout 给 CLI 反馈。

**模型族适配**:`o3`/`gpt-5.*` 用 `max_completion_tokens` 且 ≥32768(`:26-37, 422-426`);`o3*`/`o4-mini` 不支持 temperature(`:39-44`);Claude/DeepSeek/Qwen 或 `responses` API 不支持 `response_format`,改在 system 注入 JSON 指令(`:428-461`)。MetaClaw bridge 走代理,URLError 时回落直连(`:143-156, 482-504`);Anthropic provider 走 `AnthropicAdapter` 直连 Messages API(`:169-176`)。

## 12. HITL 人机协作(`hitl/`)

**6 种策略**(`InterventionMode`,`config.py:10-18` + presets `:200-243`):
| 模式 | 行为 |
|------|------|
| full-auto | 不暂停 |
| gate-only | 仅 5/9/20 要审批 + 可改产物 |
| checkpoint | 相位边界(2/6/8/11/13/15/19/23)暂停 |
| step-by-step | 每阶段后暂停 + 流式输出 |
| co-pilot | 协作阶段(7/8/9/17)开启 collaboration,审批阶段(5/8/9/15/20)要批准 |
| custom | 用户自定义每阶段 `StagePolicy` |

`StagePolicy`(`config.py:29-57`)是细粒度开关:`pause_before/after`、`require_approval`、`stream_output`、`allow_edit_output/inject_prompt`、`enable_collaboration`、`min_quality_score`、`max_auto_retries`、`human_timeout_sec`。

**`HITLSession` 运行时**(`session.py`):`pause()`→`wait_for_human()`→`resume()`。`wait_for_human()` 优先调注册的回调;否则轮询 `run_dir/hitl/response.json`(供 `attach`/web/MCP 外部工具异步重连,数小时后也能接上);都没有则超时自动批准。每次介入记入 `interventions` 日志(时长/动作/结果)。CLI 的 `attach/status/approve/reject/guide` 就是读写这些文件与运行中会话通信。

## 14. 设计要点总结(为什么这样设计)

| 机制 | 设计意图 |
|------|---------|
| 闸门成功不写 checkpoint,批准才写 | 续跑总从"人类批准的里程碑"开始,被拒不留脏 checkpoint |
| hep_ph 强制 stage10 闸门 | 烧算力前必须人审对撞机方案 |
| PIVOT 改名 vs agent-REFINE 复制 | 普通重跑要干净状态;agent 增量改进要保留工作区 |
| `_promote_best_stage14` + BUG-226 | 论文用最优轮数据,防退化轮污染 |
| 强制 PROCEED + 质量警告 | 防死循环,宁可产带警告的论文 |
| 原子 checkpoint(temp+rename) | 崩溃不留半截损坏文件 |
| 输入校验前置、快速失败 | 阻止级联错误 |
| 版本目录去优先 | 一次坏重试不污染下游 |
| 剥 `<think>` / JSON 四级容错 | 抗推理模型思维链和脏输出 |
| 模型链 + 退避抖动 | 对用户透明的高可用 + 防惊群 |
| 真实指标注入 + 数字消毒 + 引用核验 | 三道防线对抗 LLM 编造 |
| Protocol 适配器 + Recording 桩 | 松耦合、可测试 |
